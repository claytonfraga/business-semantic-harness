## SPARQL selection and limits

Comunica RDF/JS Lite **5.4.1** was selected after Context7 and first-party documentation research. No dedicated installed Context7 skill file was available; the library resolver and documentation tools were used. The installed API was checked against retrieved snippets, including correcting the stale `queryAsk` example to `queryBoolean`. See `docs/sparql-library-selection.md` for sources and the Oxigraph comparison.

The optional interface supports local read-only SELECT/ASK with typed terms, joins, FILTER and paths. A worker enforces query termination and explicit result limits. UPDATE, SERVICE and remote dataset clauses are rejected. Empty output, false ASK, failures and timeouts never become authorization. General queries remain distinct from SHACL-SPARQL constraints; there is no RDF/OWL inference.

No library speed superiority, cost savings or architectural adequacy has been empirically established. Native token budget limits requested output per model turn, not all input tokens. Custom generator callbacks must honor cancellation to stop side effects. Pure SHACL timing is not isolated from governance overhead. Nonblob Git objects require a separate source-capture contract. Human, deployment and maintenance cost observations must be supplied by the evaluation owner.

Global npm installation emitted the existing OpenTUI Node-engine warning and a Bun install-script warning. The installed package-local Bun binary and OpenTUI module were explicitly checked successfully; no interactive runtime claim follows from those checks.
